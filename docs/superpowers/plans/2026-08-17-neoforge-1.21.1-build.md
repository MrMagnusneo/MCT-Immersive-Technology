# MCT Immersive Technology NeoForge 1.21.1 Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a reproducible, content-complete NeoForge 1.21.1 gameplay JAR and a PR targeting `1.21.1-3.0-Dev`.

**Architecture:** Keep the existing NeoForge port and repair it in place. Add repository-level invariant tests first, then use compiler, datagen, and server-startup failures as ordered migration evidence while preserving the existing registry and resource surface.

**Tech Stack:** Java 21, Gradle wrapper, NeoForge ModDevGradle 2.x, Minecraft 1.21.1, Immersive Engineering 1.21.1, JUnit 5, shell-based JAR inspection.

## Global Constraints

- Base branch is `1.21.1-3.0-Dev`; implementation branch is `codex/neoforge-1.21.1-build`.
- Start from NeoForge `21.1.234`, Immersive Engineering `1.21.1-12.4.2-194`, JEI `19.27.0.343`, Parchment `2024.11.17`, and Java 21 as pinned by the branch; change a pin only when dependency resolution proves it incompatible and record the replacement.
- No registry entry, multiblock, recipe, asset, localization, sound, manual entry, or integration may be removed or replaced with a no-op.
- The final gameplay JAR must not depend on an undeclared local sibling checkout.
- Every completion claim requires fresh command output; the full clean build must pass three times.
