# MCT Immersive Technology NeoForge 1.21.1 Build Design

## Goal

Produce a verified NeoForge 1.21.1 gameplay JAR from `1.21.1-3.0-Dev`, preserve all mod content, and submit required fixes through a pull request targeting that branch.

## Branch strategy

- Treat `1.21.1-3.0-Dev` as the canonical NeoForge 1.21.1 branch. Its use of `net.neoforged.moddev`, the `neoForge` Gradle extension, NeoForge dependency coordinates, and `META-INF/neoforge.mods.toml` establish the loader unambiguously.
- Develop fixes on `codex/neoforge-1.21.1-build` and target `1.21.1-3.0-Dev` with the pull request.
- Do not create a parallel loader branch unless inspection later reveals Forge-only production code that cannot be corrected in place.

## Implementation scope

- Repair build scripts, dependency resolution, source compatibility, generated data, metadata, and packaging as required for Java 21, Minecraft 1.21.1, NeoForge, and the matching Immersive Engineering release.
- Preserve every existing block, item, fluid, entity type, menu, recipe type, multiblock, configuration option, integration, asset, data file, localization, sound, and manual entry.
- Resolve the mandatory Immersive Convergence dependency explicitly. The final build must not rely on an undeclared local-only JAR.
- Do not delete features, comment out registrations, or introduce no-op placeholders merely to make compilation succeed.

## Validation

- Capture a baseline inventory of Java registration identifiers and resource/data paths before edits and compare it with the finished branch.
- Run unit tests, data generation with validation, and a dedicated-server startup smoke test.
- Run a clean full Gradle build three times and inspect each resulting gameplay JAR.
- Verify that the JAR contains `META-INF/neoforge.mods.toml`, compiled entry points, assets, generated data, mixin configuration, and required service metadata.

## Deliverables

- Gameplay JAR for NeoForge 1.21.1.
- Source changes on `codex/neoforge-1.21.1-build`.
- Pull request into `1.21.1-3.0-Dev` with validation evidence and any runtime caveats.
